# Validation Boundary

## Statement

CSV Evidence Tracker is a portfolio prototype. It demonstrates concepts relevant to computerized-system validation (CSV), evidence traceability, and data integrity. It is not a validated system and does not itself meet 21 CFR Part 11, EU Annex 11, GAMP 5, or any organization-specific quality-system requirements.

## Included prototype capabilities

- Synthetic requirements, test cases, executions, deviations, and audit records
- Requirement-to-test traceability views
- Demonstration workflows for IQ/OQ/PQ and deviations
- Basic application audit-log concept
- Dockerized local-development configuration

## Controls required before production use

| Area | Production requirement |
|---|---|
| Intended use | Approved intended-use statement, GxP assessment, and system classification |
| Quality governance | Validation plan, procedures, roles, training, and approvals |
| Risk management | Documented risk assessment with controls and test coverage |
| Validation | Approved URS, design evidence, IQ/OQ/PQ protocols and reports, traceability, and release authorization |
| Security | Authentication, authorization, least privilege, secure sessions, and vulnerability management |
| Electronic records | Controlled retention, backup/restore, disaster recovery, and data-integrity controls |
| Audit trail | Secure, computer-generated, time-stamped, reviewable, protected audit trail with appropriate retention |
| Electronic signatures | Identity verification, signature manifestation, record linkage, and procedural controls |
| Change control | Formal impact assessment, approval, testing, and release process |
| Operations | Monitoring, incidents, periodic review, CAPA, and supplier oversight |

## Data integrity

The prototype uses synthetic data only. A regulated deployment should support ALCOA+ principles: attributable, legible, contemporaneous, original, accurate, complete, consistent, enduring, and available.

## Safe language

Use: “21 CFR Part 11–aligned concepts,” “CSV workflow prototype,” and “designed with traceability and auditability in mind.”

Avoid: “validated,” “Part 11 compliant,” “production-ready,” or statements implying regulatory acceptance.
