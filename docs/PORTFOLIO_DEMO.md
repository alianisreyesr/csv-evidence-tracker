# Portfolio Demo Guide

## Purpose

Use this 3–5 minute walkthrough to present the CSV Evidence Tracker as a portfolio prototype. Describe it as a technical and quality-oriented demonstration—not as a validated or production-ready GxP application.

## Walkthrough

1. **Dashboard:** Explain how the dashboard centralizes validation evidence, progress, risk, and open quality work.
2. **Requirements Traceability Matrix:** Select a requirement and show its risk classification, linked test cases, and execution evidence. An absent or incomplete link is a traceability gap.
3. **Test Queue:** Show IQ, OQ, and PQ records, their planned status, and their execution outcome. All records are synthetic.
4. **Deviations:** Walk through a deviation from identification and impact assessment to investigation, follow-up action, and closure.
5. **Audit Log:** Explain that an attributable record of actions, timestamps, and affected objects supports auditability. The prototype illustrates the concept; it is not an immutable production audit trail.

## Recruiter narrative

> I built this project to combine data-engineering skills with regulated quality workflows. It models requirements-to-test traceability, validation evidence, deviation management, and auditability concepts through a FastAPI and React application with synthetic data. I intentionally scoped it as a portfolio prototype; a real GxP deployment would require formal intended use, risk assessment, validation, security controls, and quality-system governance.

## Demonstration checks

- Confirm that the data is synthetic.
- Show one requirement-to-test-to-execution relationship.
- Identify one open deviation or traceability gap.
- State the validation boundary before discussing 21 CFR Part 11.
- Do not describe the prototype as validated, compliant, or suitable for production use.
